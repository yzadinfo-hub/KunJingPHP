## 三、半年路线图（6 阶段）

| 阶段 | 周次 | 主题 | 核心交付 | 业务结合 |
|------|------|------|----------|----------|
| **Phase 7** | W1~4 | 工程化与质量基石 | 提交 3 处改动 + 清残留；GitHub Actions CI；PHPUnit 迁移（Cache/Validate/Collection 先行）；`config:cache` | 所有后续更新的安全网 |
| **Phase 8** | W5~8 | 服务容器与扩展机制 | `ServiceProvider` + 自动发现；延迟加载；扩展包骨架；字典/权限/导入导出抽包 | 组梦ERP 公共组件沉淀 |
| **Phase 9** | W9~12 | 认证与安全 | `Auth`（session + token + guard）；`Hash` / `Crypt`；RBAC 权限；上传白名单与 CSRF 增强 | 电商客服多店铺、VIP 会员 |
| **Phase 10** | W13~16 | 异步与调度 | `Queue`（DB / Redis 驱动）；`Schedule` 计划任务；`queue:work` / `schedule:run` 守护命令 | GEO 日巡检、AI 推理异步化 |
| **Phase 11** | W17~20 | 存储与 API 集成 | `Storage`（本地 / COS / OSS）；`Mail`；`API Resource`；内部 `HTTP Client` | 组梦AI 文件、电商多平台对接 |
| **Phase 12** | W21~26 | 数据层深化 + 发布 | SQLite/PgSQL 实跑 + 读写分离；软删除/Scope 完善；分模块手册；CHANGELOG + v1.0 tag | 全框架收口与对外发布 |

### 每阶段的「完成 definition」

- 有对应 `tests/phaseN.php`（沿用零依赖脚本断言）或 PHPUnit 用例，**全绿**；
- 有 `docs/模块手册-XXX.md`，README 进度表同步更新；
- 至少 1 次可直接 `git push` 的原子提交（每阶段 4~8 次提交）。

## 四、每周节奏建议

```
第 1 周（功能周）：实现一个子能力 + 配套用例 → 提交
第 2 周（加固周）：补文档 / 修边界 bug / 重构 → 提交
       ↓ 每 4 周形成一个完整 Phase
```

- 每次提交只做一件事，commit message 用 `feat:` / `fix:` / `docs:` / `test:` 前缀；
- 每月末跑一次全量回归 + 更新 README 进度表，作为阶段收口；
- 半年末打 `v1.0.0` tag，写 CHANGELOG。

## 五、风险与前提

1. **PHP 环境缺失**：本机 `/c/laragon` 目录已消失，PATH 仍指向旧路径。必须重装/恢复 PHP 8.1+（含 `pdo_mysql`），否则测试与 CLI 生成器均不可用。
2. **未提交改动**：3 个文件 + `.bak` 长期游离，存在丢失与「本地行为和仓库不一致」风险，优先处理。
3. **避免为对标而对标**：每个 Phase 都绑定真实业务需求；没有使用场景的能力（如 Mail）可后置。
4. **零外部依赖原则**：HTTP Client / Storage 驱动均自研封装，不引入 GPL 依赖，保持 MIT 兼容。
5. **clean-room 红线**：文档与代码不出现第三方框架的品牌/命名空间；新模块命名继续自主。
